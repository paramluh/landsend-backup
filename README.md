# Landsend rental-cluster backup

Private backup for **paramluh**, initiated October 31, 2026 before the cluster rental ends at midnight America/Los_Angeles.

This repository contains otherwise-unversioned source code, configuration, recovery scripts, and backup receipts. Files under `files/` retain their original absolute paths with the leading slash removed. Credentials and private keys are excluded; recognized credential values in text are redacted. Remote-node orphan source is additionally stored under `remote-files/`, deduplicated against existing source. Run `python3 restore_remote_code.py --destination /path/to/code-recovery` to reconstruct every recorded remote source pathname from Git alone; `reports/remote-orphan-code.json.zst` records the content mappings. The full bulk backup also contains these files.

Large experiment artifacts, logs, conversation samples, dataset derivatives, and archived working copies are stored in the private Hugging Face dataset **[InternalCan/landsend-artifacts-backup-param](https://huggingface.co/datasets/InternalCan/landsend-artifacts-backup-param)**. Personal Hugging Face storage rejected the first archive because its private-storage quota was exhausted; the GitHub repository remains in the requested personal account. Archive receipts include SHA256 hashes. Download the current `main` tree, which includes sanitized replacements and all completed deltas; historical per-upload commit IDs are audit details and may no longer resolve after the credential-removal history cleanup. `reports/cluster-backup/artifact-history-cleanup.json` records the verified clean revision. The dataset contains deduplicated Zstandard-compressed tar archives and manifests describing original paths and hardlink aliases.

Existing Git repositories are backed up to branch **`tmp/landsend-backup-param` in their original repositories**. Separate Git backup receipts list those repositories and commits. Existing checkpoint backups and any newly uploaded checkpoint files are tracked by the checkpoint inventory; they are not duplicated into GitHub.

## Restore

1. Clone this private repository.
2. Install `huggingface_hub` and the `zstd` command, then authenticate to Hugging Face with an account that can read the private dataset and referenced existing repositories.
3. Download the private dataset with `hf download InternalCan/landsend-artifacts-backup-param --repo-type dataset --local-dir hf-backup`.
4. Run `python3 restore_archives.py hf-backup --destination /path/to/recovery`. This verifies archive hashes, restores each host into its own subdirectory, and includes completed artifact, source-archive and dataset groups plus later deltas in completion order. Newer deltas replace earlier files. It restores hardlinks, empty directories and internal user-file symlinks. To restore one host directly under the destination, add `--host landsend-0`. External/system symlink targets remain in `metadata/symlinks.json` for review. Verified parts from partial archive sets are recovered too, with warnings; use `--complete-only` to skip them. It does not overwrite original cluster paths unless you explicitly select one host and choose `/` as destination.
5. Restore the 25,011 dataset files proven identical to existing HF revisions with `python3 restore_existing_datasets.py hf-backup/landsend-0/datasets/metadata/verified-existing-datasets.json --destination /path/to/recovery/landsend-0`. These 290.08 GiB are referenced by pinned revision and verified hash rather than duplicated into the bulk backup. Unique dataset derivatives are included in the archived `datasets` set. For other hosts, run `restore_remote_dataset.py` with that host's `datasets/verification/verification.json` from the HF backup, its restored dataset directory, the node-zero dataset directory and its cross-node aliases. This fills pinned-HF and cross-host references, then verifies every file. See [RESTORE_DATASETS.md](RESTORE_DATASETS.md) for the complete invocation and verification behavior.
6. Overlay any newer files from this repository's `files/` directory, inspect the manifests, and restore original repository working copies using [RESTORE_GIT.md](RESTORE_GIT.md).

Backups are being completed incrementally. An archive set is complete only when its remote `COMPLETE.json` exists and all listed archives pass verification. Final receipts distinguish completed uploads, already-remote datasets/checkpoints, exclusions, and any remaining gaps. Regenerable package/compiler/browser caches and authentication stores are intentionally not copied.

Archive copies are inspected recursively, including compressed source tarballs and nested Git bundles. Credential-bearing copied files are redacted; original source files and home-repository history are not modified by the artifact sanitizer. For rewritten bundle copies, `reports/cluster-backup/git/sanitized-bundles/` contains source/output fingerprints and old-to-new commit maps. Restore uses the sanitized artifact hashes recorded by the final receipts.
