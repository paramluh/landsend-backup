# Transcript-conditioned inference

Both fine-tunes use the existing BF16 PPM engine with the production Xabi voice
prefix, two-frame media delay, speech/pose towers, depth decoders, and D33 link.
The default is **zero ground-truth audio/pose prefill**. Two GPUs with enough
free memory for the 44B model are required; the tested cluster uses H100 80 GB.

| Recipe | Prefix after the voice/system block | Generation |
| --- | --- | --- |
| `aligned-media` | SOP, complete frame-aligned word/PAD/NEW_WORD lane, EOP | Supply that same lane framewise; sample audio and pose |
| `compact-all` | SOP, ordinary tokenized transcript, EOP | Sample text, audio, and pose framewise |
| `xabi-original` | Original Xabi voice/system block only; no transcript prefix | Supply the aligned lane framewise by default; `--text-mode native` samples text, audio and pose |

`xabi-original` loads production Xabi step 200 from
`InternalCan/ppm-aloe-v2pure-main-17850-final` at
`7beed89de7ca01803cf84ff2c4bff928322403c7`, installed under
`/home/param/models/transcript-pose/xabi-original/export-200`.
`run_xabi.sh` selects this baseline. Its framewise words and voice conditioning
match the aligned recipe; only the learned checkpoint and upfront transcript
conditioning differ. It uses no ground-truth generation audio or pose.

The entire prefix is processed into the backbone **and both tower caches** before
generation. The two transcript fine-tunes use SOP/EOP IDs 151680/151681 and
start generation after EOP. Xabi has no transcript block. Positions continue
through each prefix; they do not restart at EOP.

## Run the new checkpoints

```bash
cd /home/param/pose-repo
source finetune/transcript_pose/environment/activate.sh
export MIMI_DIR=/path/to/local/mimi

# Fixed timed transcript, copied upfront and then supplied framewise.
python infer/transcript_pose/infer.py \
  --recipe aligned-media --words /path/to/words.json --seconds 8 \
  --voice-clip /path/to/same-speaker.wav --devs 0,1 --out /path/to/aligned-output

# Ordinary full transcript upfront; timing/text lane generated by the model.
python infer/transcript_pose/infer.py \
  --recipe compact-all --transcript 'Here is the complete transcript to perform.' \
  --seconds 8 --voice-clip /path/to/same-speaker.wav \
  --devs 0,1 --out /path/to/compact-output
```

`run_aligned.sh` and `run_compact.sh` select the corresponding recipe. The default
checkpoints are `/home/param/models/transcript-pose/<recipe>/export-200`.
Override with `--ckpt` when moving to another machine. An export must contain
**all 56 rank shards**, `rep.pt`, `meta.json`, and `COMPLETE`; one training node's
export directory alone is incomplete. `--tokenizer` defaults to the complete
tokenizer assets in the downloaded step-17850 base package.

Use `--no-voice-clip` for the empty system block. A supplied voice reference is
encoded with Mimi, must be at least 38 frames (about 3 s), and is cropped to 125
frames (10 s). This is a same-speaker voice reference, not initial output media.
No persona or visual/geometry conditioning is added to PPM.

`words.json` accepts `[[start_seconds, end_seconds, "word"], ...]`, or dictionaries
with `start`, `end`, and `text`. The original training word-cleaning, tokenization,
and NEW_WORD placement helpers construct the lane. Alternatively `--lane` accepts
a one-dimensional integer `.npy` array containing the complete lane; its length
defines the duration. `--transcript-file` accepts UTF-8 plain text for compact-all.

The compact model has **no trained end-of-output or duration head**. Supply
`--seconds` or `--frames`; EOP ends conditioning, not the generated performance.
With no prefill its first generation text frame is initialized to PAD, the
existing engine's cold-start policy. That first text frame had no prediction
loss during training. Every subsequent frame is sampled, including word timing;
the supplied transcript is conditioning, not a guarantee of verbatim output.
The final two text slots are forced to PAD while the last delayed media frames
are generated, matching training.

## Reproduce a held-out input

```bash
python infer/transcript_pose/infer.py \
  --recipe aligned-media --clip-index 3142 --frames 56 \
  --devs 0,1 --out /path/to/heldout-aligned

python infer/transcript_pose/infer.py \
  --recipe compact-all --clip-index 3142 --frames 56 \
  --devs 0,1 --out /path/to/heldout-compact
```

Cache indices use `CompactXabi.clips`, not the ordinal within the eval split.
With no custom text or clip index, the first held-out clip is selected. The
cache path defaults to `/home/param/datasets/xabi-v2pure-cache`. Cached inputs
reconstruct exactly the training voice draw and reference; the generation
audio/pose arrays are then cleared. Only `--prefill-frames N` explicitly supplies
ground-truth initial media and its corresponding timed words. `--start-frame`
selects a crop while retaining the original frame-zero pose geometry.

`--prepare-only` writes `inputs.npz` and `input.json` without loading PPM. Those
files record the exact prefix, supplied lane, source crop, voice reference,
two-frame delay, and prefill policy. Full input + prefix + delayed generation
must fit the training limit of 7500 positions; split a longer request explicitly.

## Outputs and video bridge

Every run writes `tokens.npz`, `mimi.safetensors`, `pose_tokens.safetensors`,
`words.json`, and `meta.json`. Mimi and pose code arrays have shape `[32, frames]`
at 12.5 Hz with local IDs 0–2047. Unless `--no-audio-decode` is set, `audio.wav`
contains 24 kHz decoded speech. Sampling defaults are temperature 1, audio/pose
top-k 0 (unfiltered), no repetition penalty, no pose CFG; the effective settings and seed
are recorded in metadata. `--temp 0` selects greedy decoding.

`--pose-latents` and `--skeleton-video` use the pinned production pose tokenizer
and Electron bridge. Provide `--frame0` (`frame0_pose` in a safetensors file or a
`.npy` array, shape `[133,3]`, **y, x, confidence in pixels on a 480×256 canvas**)
or `--package` containing `llm_inputs.safetensors`. The 55 joints used by the
tokenizer must be populated. Geometry is used only to decode/render pose, not
as conditioning for either PPM checkpoint.

Rendering requires an **even** number of 12.5 Hz frames; the CLI rejects odd
counts rather than silently trimming pose and desynchronizing audio. Pose is
decoded to 25 Hz; the Electron encoder repeats the final pose frame once for
its 1+4k frame convention. `--video-sample` additionally needs an identity package
with `sink_latent.safetensors` and `meta.json`; it creates `video_sample/`
for the diffusion runner. Reference-bank conditioning is supplied separately to the video runner. It does not use that package's ground-truth
audio or pose as a PPM prefill.

Local codec locations can be set with `POSE_TOKENIZER_DIR`, `ELECTRON_ENCODER`,
and `MIMI_DIR`. `FA3_DIR` defaults to the training kernel cache when present.
Pose rasterization needs `nvcc`, Ninja and Python headers; the training
environment activation script supplies the existing headers.

The bank layout is `<bank>/<actor-id>/property_1..9/latents.safetensors`, key
`video`, shape `[N,48,30,16]`. One image is chosen per available property using
NumPy seed `[1234, crc32(clip_key) & 0x7fffffff]`, independently of sampling seed.
Retain the original appearance clip key when relocating assets. Missing
properties remain masked; never duplicate other references to fill them.
The appearance sink, frame-zero geometry, and bank must belong to the same
identity/crop. The pose geometry is a rendering anchor, not PPM conditioning.

`render_video.py --prepare-only` stages inputs, writes the exact config, and
runs the upstream `--check` validation without using a GPU. The full command
then invokes `python -m inference.distilled`. Paths to the source, interpreter,
student, Mimi and VAE are overridable. Sampling uses eight stabilizer steps
(two in each of four noise bands), then one resolver step with the unchanged
stabilized tensor. Runtime guidance is 1, renoising is off, and both modes use
the same student and selected references. Compilation, CUDA graphs, and
full-wavefront sampling remain enabled.

The supplied sink has shape `[1,48,30,16]`, key `latents`. Only that video latent
is conditioned on. The wrapper fills later video input slots with zeros solely
to declare timeline length; generation uses its own history. The audio file is
the PPM's **generated** Mimi code sequence. The legacy input filename
`mimi_local.safetensors` does not imply waveform re-encoding.

The inherited video loader uses `L = min(pose_latents, audio_frames // 2)` and
decodes `4L-3` RGB frames. Thus 56 audio frames (4.48 s) produce 109 video frames
(4.36 s); 100 audio frames (8 s) produce 197 video frames (7.88 s). The last
120 ms are cropped at the boundary, with no time shift or resampling. Staging
also trims the final padding pose latent to give the input files equal lengths.
`input.json` records duration and source provenance. `--max-latent-frames` can
request a shorter smoke test. Outputs are `generation/video.mp4`, clean and
stabilized latent files, and `generation/status.json`; success is `complete`.

The local smoke-test identity `appearance-10_27286bdd` uses a historical
muon-encoded reference bank copied read-only from Amu's demo. All nine property
files match the repository's historical v2 audit manifest by SHA-256. This does
not establish that they match the newer Richmond strict bank. The wrapper
records each reference file's hash and includes the bank's provenance report in
`input.json`. The smoke-test appearance identity also differs from the source
of the PPM transcript and voice; these samples verify integration, not a
controlled comparison against production evaluation data.

The current run lives at `/home/param/pose-runs/controlled-comparison-20261028`.

`infer_batch.py --recipe RECIPE --batch-json jobs.json --devs 0,1` accepts one
or two rows. Forced text is mandatory in this entrypoint. Each JSON row has
`clip_index`, `start_frame`, `frames`, `voice_clip`, `seed`, and `out`. Independent

batch composition. The full-model batch/row-order audit must pass before the

GPU work or process termination on landsend-0 and never accesses landsend-12.

forced text lane, no ground-truth generation media, all code ranges, audio

and per-cell conditioning/provenance metadata.

The eight clips use fresh same-track HF property images because their

## Website requests

The request studio uses `request_schema.py` and `request_worker.py`. Requests
select one of the eight prepared clips and one checkpoint, with independent
audio/pose temperatures and top-k values, a generation seed, a video seed, and
an integer duration from 4 to 60 seconds. `text_mode=forced` is the default and
retains the prepared framewise word/PAD/NEW_WORD lane for all three models.
`text_mode=native` lets compact-all generate text and timing from its ordinary
upfront transcript, or lets xabi-original generate without a transcript. Native
requests also expose text temperature and top-k. Aligned-media remains forced,
matching its audio/pose-only training objective.

Every mode retains the original eight-second voice reference, pose rendering
geometry, appearance sink and nine-image reference bank. Native generation
receives no source framewise text: its first text frame is the engine's cold
PAD bootstrap, subsequent frames are sampled, and two final PAD slots flush
the delayed media. Source transcripts remain provenance only for native Xabi.
Duration selects the beginning of the prepared clip; compact uses the transcript
for that interval. Native word timing is generated, so it need not match the
controlled comparison. Custom transcripts and arbitrary input paths are not
accepted. Defaults are temperature 1 and top-k 0 (unfiltered) for all sampled
modalities; temperature 0 selects greedy decoding.

`request_dispatcher.py` schedules requests across all 32 GPUs on landsend-1
through 4. Each PPM job gets two free GPUs on one node. Its second GPU becomes
available immediately when PPM exits; pose/video rendering continues on the
first GPU. That GPU is released when rendering finishes, before CPU validation
and transfer. New jobs can use any two available GPUs on a node, including GPUs
released by other jobs. Up to sixteen PPM jobs can run simultaneously, with
additional overlap between generation, single-GPU rendering and CPU work.

The CPU scheduler runs as `param-inference-request-dispatcher.service` on node 1,
installed from `request-dispatcher.service`. The old serial worker service is
disabled. Detached executors survive scheduler restarts; durable claims,
process identities and per-GPU locks prevent duplicate execution. A missing
model export makes that node ineligible for that model until its copy completes.
All paths and parameters are revalidated by each executor. Completed artifacts
are transferred privately and checked before their final video appears online.

The central queue remains `/home/param/pose-runs/inference-requests-20261028/jobs`.
Each UUID directory contains its request, state, assignment, progress snapshots,
and completed result. Remote executions live under
`/home/param/pose-runs/inference-request-executions-20261028/jobs` on their assigned
nodes. `dispatcher-status.json` reports current assignments and available GPUs.
Creating `DISPATCH_STOP` in the central queue root pauses new assignments while
existing jobs continue. The scheduler never allocates node 0 or node 12. The
website frontend and authenticated API are in the sibling `pose-demo-website`
repository's `comparison/` directory.

### Rasterized pose views

Completed videos also publish **Pose overlay** and **Pose only** views. Both use
the same frame grid and unchanged audio as the original video; the player keeps
its playback position when switching. These show the generated conditioning
pose, not a pose estimate extracted from the finished RGB video.

`pose_views.py --video VIDEO --pose-dir POSE_DIR --out OUTPUT_DIR` creates the
views on CPU. It reuses `skeleton.mp4` when available, or reconstructs older
previews from saved pose tokens and the original `--frame0` geometry using the
pinned tokenizer. Output is `pose.mp4`, `overlay.mp4`, and an atomically published
`pose-views.json` receipt. Validation checks frame count, timebase, source and
output hashes, full video decoding, and identical compressed and decoded audio.
Future request workers save the production skeleton during their existing pose
stage, then make the new views after releasing their GPU allocation.
